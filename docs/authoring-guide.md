# Setdraft 出题文档

这份文档按工作台的实际操作顺序介绍普通题、交互题和竞赛题册。题目内容自动保存，发布包保存已验证的版本；竞赛引用发布包，不直接引用还在编辑的草稿。

## 1. 开始之前

登录后在“制题工作台”新建题目，选择 ACM 或 OI。ACM 要求全部测试点通过；OI 使用子任务分值。计分方式创建后固定，是否交互与计分方式独立。

先填写题目标题、标识、标签、时间限制和内存限制。时间单位为 ms，内存单位为 m。确认工作台显示沙箱就绪；沙箱未就绪时仍可编辑和保存，但不能完成程序验证。

推荐先完成一个最小可运行题目，再逐步增加边界数据和复杂场景：题面 → 一个样例 → 标准程序 → 一个私有测试点 → 验证 → 补齐覆盖 → 发布。

## 2. 普通题和交互题怎么选

在题目配置中开启“交互题”，题面和程序配置会随之切换。关闭后恢复普通题配置；切换不会删除被隐藏的代码、题面栏目、数据或子任务。

| 配置 | 谁读取测试输入 | 如何判断答案 | 活跃测试数据 |
| --- | --- | --- | --- |
| 普通题 | 选手程序 | 文本比较或 testlib Checker | 输入及标准答案 |
| 交互题 · 全交互 | 交互器，不预置任何内容 | 交互器双向通信后判定 | 自动生成一个严格空 `.in` 和空答案 |
| 交互题 · 半对拍 | 交互器，输入不直接交给选手 | 交互器双向通信后判定 | 作者提供私有 `.in`，答案为空 |

本项目的“半对拍”仍是交互题，不是普通程序读取 `.in` 后用 Checker 单向判定，也不使用 DOMjudge 的 `special_compare`。全交互和半对拍都使用同一套交互执行、隔离和导出流程。

本轮不包含通信题、Alice/Bob、grader 或 multi-pass。

## 3. 分栏编辑题面

普通题分为“描述、输入、输出、提示、样例”；交互题分为“描述、交互描述、提示、样例”。每个栏目填写正文即可，不必重复写栏目标题。右侧预览使用完整题面，发布和导出采用同一份内容。

- 描述：定义问题、目标、符号和约束。不要把只能由裁判知道的测试数据写进题面。
- 输入：说明普通题输入格式、各字段范围、组数和特殊值。
- 输出：说明普通题输出格式、允许误差以及多解时的判定标准。
- 交互描述：说明谁先发送消息、每种消息的格式、查询上限、错误反馈、结束条件，以及 flush 要求。
- 提示：放样例解释、补充约定和容易混淆的边界条件。
- 样例：单独维护公开展示的数据或协议示例。

旧项目的完整 Markdown 会原样保留在“描述”中，不会自动猜测并拆分。首次按分栏编辑时，把旧的输入、输出和提示移到对应栏目，并检查预览中没有重复标题或样例。切换交互模式时，普通题的输入/输出正文保留；切回普通题时，交互描述也不会被删除。

## 4. Markdown、公式与附件

支持标题、列表、表格、引用、代码块、脚注和常用数学公式。行内公式使用 `$a_i$`，独立公式使用单独成行的 `$$`。浏览器预览不执行 Markdown 中的原始 HTML 或脚本。

例如，在描述中填写：

```markdown
给定两个整数 $a,b$，求 $a+b$。

保证 $-10^9 \le a,b \le 10^9$。
```

附件上传后使用 `![示意图](file://graph.png)` 引用，也可以直接复制界面提供的引用文本。文件名使用字母、数字、点、下划线或短横线，首字符使用字母或数字。单个附件最大 1 MiB。

竞赛 PDF 的图片使用已上传的 PNG、JPEG、GIF 或 SVG 附件；外部图片 URL、缺失附件和不支持的图片格式会让 PDF 生成失败。不要依赖联网图片来准备离线题册。PNG、JPEG、GIF 每边最多 8192 像素、单张最多 1600 万像素，一次生成的位图总计最多 6400 万像素。

SVG 仅支持白名单内的基本形状、文字和渐变，单文件最多 256 KiB、5000 个节点、32 层嵌套。不支持嵌入位图、脚本、样式、外链、`use`、滤镜、DTD 或实体声明；渐变只能引用本图内的 ID。复杂 SVG 请转换为符合尺寸限制的 PNG 后上传。

普通网页预览和 PDF 排版使用不同的公式渲染器。PDF 公式中禁用 `\includegraphics`，插图必须改用公式外的 Markdown 附件引用。`\hspace`、`\vspace` 和 `\raisebox` 的长度只接受“数值 + 单位”，例如 `2em` 或 `-1.5pt`；支持 `pt`、`bp`、`pc`、`mm`、`cm`、`in`、`em`、`ex`、`mu`、`sp`，数值绝对值不能超过 10000，不接受表达式或代码。复杂宏、极宽表格和长代码行应在题册预览中再检查。

PDF 不是原始 Typst 或 LaTeX 执行入口。题面文本按 Markdown 转换，原始 `#include` 等内容作为文本处理；公式适配层限制文件读取、代码求值和文档查询等入口。首页补充说明建议只使用文字、列表、表格和公式。这些输入限制不等同于独立的操作系统安全沙箱，部署仍需保留容器及资源限制。

## 5. 公开样例与私有测试数据

在“题面 → 样例”添加、修改或删除公开样例；最多 20 组，每侧最多 200000 字符。普通题的样例按输入/输出配对，发布验证时运行标准程序核验。样例会出现在结构化题面和竞赛 PDF 中，不要再手工复制一遍到描述中。

交互题的两栏表示“交互器发送”和“选手发送”，只用来说明协议，不按普通输入输出直接运行。存在多轮交替通信时，应在交互描述或提示中标清消息顺序；两栏不能替代协议说明。公开样例不充当交互器的私有测试数据。

私有数据在“测试数据”页管理。手动输入适合短数据；大数据上传 `.in` 和同名 `.out` 或 `.ans`。例如 `1.in` 对应 `1.out`，不要同时给同一点上传两份含义不同的答案。普通题缺少答案时，可在验证时由标准程序生成；已经上传的答案仍需通过验证。

普通题样例与私有测试点分开导出；DOMjudge 分别放在 `data/sample` 和 `data/secret`。交互题不生成 DOMjudge 样例测试点，协议示例只在题面中展示。

批量删除和重新编号前检查选中范围。手动数据和 Gen 生成数据分别管理；重新运行 Gen 用新的完整批次替换旧生成批次，失败时保留上一批。修改手动数据或生成配置后，按页面提示重新运行 Gen，再进行发布验证。

## 6. 用 Gen 批量生成数据

普通题和半对拍都可以使用 C++ Gen。沙箱提供 `testlib.h`，编译标准与界面所选 C++ 标准一致。全交互不需要 Gen，相关入口会隐藏。

生成脚本每行是一条 `gen` 命令，例如：

```text
gen small 1 10
gen small 2 10
gen large 3 100000
```

参数的含义由你的 Gen 定义。脚本支持引号参数和 `#` 注释，但不是 Shell，不执行管道、重定向或环境变量展开。每条命令生成一个测试点。

使用 testlib 的确定性随机数，或明确约定 seed 参数；不要用 `time(NULL)`、当前日期或不可复现的外部状态。系统会以相同参数重跑并比较输入哈希，结果不同会阻止成功发布。

数据覆盖至少包含最小规模、最大规模、单一/重复值、边界值、退化结构以及容易诱发错误复杂度的构造。随机数据是补充，不替代针对性构造。OI 题还要检查各子任务的约束、归属和分数。

## 7. 标准程序、Validator 与 Checker

标准程序支持 C++、Python 和 Java；C++ 使用所选标准，Java 按编辑器约定使用入口类。先确认标程能正确处理边界情况，再让它生成答案。可配置第二标准程序进行独立核验，不建议简单复制同一份算法。

Validator 检查测试输入是否符合题面约束，例如范围、行列数、空白和文件结束。它不是选手答案判定器。普通题及半对拍可选用 C++/testlib Validator；全交互不执行输入 Validator。

普通题默认文本比较。多解题、浮点误差或需要自行证明可行性时，改用 C++/testlib Checker。Checker 读取测试输入、选手输出和标准答案，用 testlib 的判定接口结束；错误数据或裁判故障应报裁判错误，不能伪装成选手 WA。

交互题隐藏普通 Checker 配置，由交互器完成判定。切换题型后原 Checker 源码仍保留，但不参与交互题运行或导出。

C++11/14/17/20/23 可选择，C++26 属实验性。目标平台必须提供对应的编译器和语言配置；本地编译成功不代表所有线上判题机都支持该标准。

## 8. 全交互：输入和答案都为空

开启交互题后，在“测试数据”选择“全交互”。系统只验证和导出一个自动测试点，`.in` 与答案均为零字节，不含换行，也不会偷偷写入 seed。

交互器从固定场景开始，或在代码中使用明确、可复现的生成规则。若希望每个测试点用不同 seed，请改用半对拍，把 seed 写入私有 `.in`。

进入“程序与交互器”，导入无输入交互器模板及配套标程。模板固定发送 `21`，标程返回 `42`，双方都 flush；可先运行此最小流程确认环境，再改为自己的协议。导入模板会替换当前编辑器中的代码，应先确认保留好已有内容。

全交互隐藏生成器、输入 Validator 和原私有数据操作，已有数据、Gen、Validator 和子任务仍保留。切回半对拍或普通题后可继续使用。OI 全交互当前按一个 100 分测试子任务导出，不采用隐藏的原数据分组。

## 9. 半对拍：私有输入，空答案

在交互题“测试数据”选择“半对拍”，上传或生成 `.in`。输入只挂载给交互器，不会作为选手程序的初始 stdin。`.ans/.out` 不需要提供内容；即使工程里有旧答案，交互判定也不读取它们，导出的答案始终为空。

使用有输入交互器模板时，可先创建内容为 `21` 的 `1.in`。模板使用 `inf` 读取私有输入，向选手发送数值，通过 `ouf` 读取选手回答并判定。需要种子生成时，先约定 seed 的格式与范围，让交互器根据 seed 确定性生成完整场景；可增加 Validator 检查 seed。

交互器与选手通过 stdin/stdout 双向通信。双方发送消息后及时 flush：C++ 可用 `std::flush` 或 `std::endl`，Python 使用 `flush=True`，Java 调用输出流的 `flush()`。调试信息写 stderr，不能混入协议输出。

交互器使用 testlib 的 `quitf(_ok, ...)` 判正确、`quitf(_wa, ...)` 判错误，非法输入或裁判自身异常使用 `_fail`。源码里不需要直接返回 DOMjudge 的 `42/43`；导出适配器会负责转换。

务必处理错误格式、超出查询次数、选手提前退出、EOF 和协议终止。选手等待交互器、交互器同时等待选手会死锁；不 flush 则可能把已写入缓冲区的消息一直留在本进程内，最终超时。

## 10. 验证报告与问题定位

点击“验证并打包”，填写本次发布名称。后台依次检查配置、编译程序、检查数据、运行标程、验证结果并生成题目包；只有完整流程成功才创建新发布包。第二标准程序存在时也必须通过，交互标程必须通过全部活跃测试点并获得满分。

在“验证报告”查看失败阶段、测试点、运行结果和日志。交互报告区分选手失败、交互器失败与系统错误。WA 表示交互器拒绝答案；RE/TLE 可能来自选手退出、崩溃、等待或超时；交互器崩溃、非法裁判状态属于系统错误，不按普通 WA 处理。

自定义 Checker 的自动格式和数值探针仅检查判分协议并显示分数。自动修改输出不保证得到错误答案，探针满分可能是合法多解；请根据题意准备已知错误输出和错误程序，独立检查 Checker 的正确性。

交互执行中双方分容器、非 root、禁网、只读根文件系统运行；选手编译和运行环境不挂载私有输入、答案或交互器源码。双方资源合计计入任务预算。每个通信方向只保留前 64 KiB 日志，截断会标注；运行输出另外有大小限制，因此日志截断不等于允许无限输出。

离开页面或退出账号不会自动取消任务。可在“任务”页查看、取消或重试；重试会创建新任务。取消运行中的交互任务时，系统先清理双方容器和相关进程，再释放调度名额。

题面、数据、程序、题型或输入模式变化都会令旧验证结果失效。不要把旧版本的成功报告当成当前草稿已经通过。

## 11. 自动保存、发布、回退与复制

自动保存成功后，内容保存在服务器个人工作区。仍显示“待保存”“正在保存”或“保存失败”时，不要直接关闭页面。登录过期会暂停工作台；同一账号重新登录可继续保存当前页面内存中的编辑，刷新页面则可能丢失尚未保存的内容。

同一题目在多个标签页编辑会触发版本冲突。先复制或备份需要保留的改动，再决定是否加载服务器版本，避免用过期页面覆盖新的内容。

“发布包”管理已验证的版本，支持命名、下载、导出和回退。题目 ZIP 用于目标评测平台；制题工程 ZIP 保留作者源码和数据，用于审计与归档，不能直接发给选手。

回退会替换当前题面、代码、附件和数据，恢复所选发布包的源内容，同时保留题目 ID 与发布历史并增加版本号。回退后须重新验证。源文件损坏或缺失时会拒绝恢复，不会静默生成不完整题目。

“复制给用户”把当前题目与数据复制成接收方的新题目，不继承发布历史、报告、聊天和任务。双方随后修改互不影响，接收方也不会因此获得原题目的访问权。文档按钮在此按钮旁，在新标签页打开本文，不打断当前编辑。

## 12. 竞赛配置与 PDF 题册

先发布各道题，再到“竞赛”新建竞赛，选择发布版本、调整题序并配置气球颜色。竞赛题目按顺序分配 A、B、C 等标签；更换题目发布版本后需重新生成竞赛包。

在竞赛内的“竞赛题面 PDF”开启“竞赛包附带 PDF”，编辑并保存以下配置：

| 选项 | 用途 |
| --- | --- |
| 竞赛名称 | 题册主标题，与竞赛本身名称一致 |
| 封面副标题 | 例如“试题册”或比赛组别 |
| 署名 / 主办方 | 首页署名与 PDF 作者信息 |
| 日期 / 地点 | 首页与页眉展示文本，不要求日期格式 |
| 首页补充说明 · Markdown | 比赛时长、注意事项和主办方说明，在封面底部居中展示 |
| 默认语言 | 中文或英文的排版栏目文字 |
| 封面语言、题面栏目语言 | 跟随默认语言或分别指定中英文 |
| 显示封面 | 是否生成首页；关闭时保留已填写内容 |
| 显示题目列表 | 是否展示题号与题名表，可独立于封面开启 |
| 显示页眉页脚 | 是否显示竞赛信息和页码 |

语言选项只改变栏目标签，不会自动翻译题面。题面正文、时间/内存限制、图片和样例来自竞赛选中的已发布版本，不采用当前未发布草稿。改变草稿后若想更新 PDF，应先重新验证发布，再在竞赛中选择新版本。

先点“保存 PDF 配置”，再点“预览题册”。有未保存的配置时，预览与竞赛导出会暂时禁用，防止把旧设置打进包。预览中逐页检查首页、中文和公式、分页、样例换行、表格、图片及题号；确认后生成 Hydro 或 DOMjudge 竞赛包。

开启 PDF 时，竞赛包包含完整题册 `booklet.pdf` 和逐题文件 `statements/A.pdf`、`statements/B.pdf` 等。DOMjudge 的逐题 ZIP 还会自动附带对应题目的 PDF，不再要求在题目工作台上传 DOMjudge PDF。历史竞赛包保持已生成的内容，不会随当前设置改写；可从竞赛发布记录下载题册。

此流程替代旧的 DOMjudge PDF 上传入口，不删除旧发布包中的已有文件。需要单题 PDF 时，可以建立只包含一道题的竞赛。关闭“竞赛包附带 PDF”后导出不会新生成题册。

PDF 直接复用 [xcpc-statement-generator](https://github.com/lihaoze123/xcpc-statement-generator) 的原模板（固定版本 `84d82230`）与八款原字体，不替换为系统字体。封面、题目列表、字号、页边距、页眉页脚和样例表均沿用原版排版；时间/内存限制按上游完整案例的 LaTeX `tabular{ll}` 排版，使用 12pt 常规文字和自然列宽，两列左对齐。PDF 栏目顺序为描述、输入/输出或交互描述、样例、提示；题目列表位于封面，关闭封面时同时隐藏。单题 PDF 按原版不显示封面和页眉页脚。首页补充说明和交互栏目保留为 Setdraft 扩展：首页说明在封面底部的题目列表、完整性提示之后居中展示，隐藏列表时仍位于封面底部，留空则不影响原版布局。题面不会自动插入评分范围表；作者主动编写的 Markdown 表格仍正常保留。

样例按原模板保留原始换行，不自动折行；过长的行需要作者调整并预览。正文使用原版 cmarker Markdown 渲染器，公式使用内置 MiTeX 0.2.6，不需要安装 TeX 或联网下载字体。为保障服务安全，不允许嵌入可执行 Typst、直接文件读取、外部图片或公式加载图片；附件只能引用已上传图片。

集成版本遵守 AGPL-3.0，原有 MIT 声明及第三方许可证保留。侧栏和 PDF 配置中的“开源与源码”提供本构建对应源码及许可文本，部署修改版本时需要保留并更新该入口。字体使用单独条款：CMU 为 OFL，New Computer Modern 为 GUST；上游未提供四款方正字体的独立分发/嵌入授权文件，公开镜像、源码包及 PDF 前需要确认相关权利，不能因模板开源而假定字体已获授权。

## 13. Hydro 与 DOMjudge 导出

Hydro 支持普通题和交互题的 ACM/OI 导出。交互题包写入 `type: interactive`、交互器源码和测试数据，并统一使用 `interactor: { file: interactor.cc, lang: auto }`，不附加普通 Checker，也不启用 `multi_pass`。全交互导出一个空输入点，半对拍导出已验证的私有输入。Hydro 根据 `.cc` 使用目标站的 `cc` 编译配置；编辑器的 C++ 标准仅控制本地验证和 DOMjudge，交互器源码仍须兼容目标站实际标准。旧发布包不改写，重新发布后才使用新配置。

DOMjudge 只导出 ACM。普通题保持普通判题流程；交互题使用 `validation: custom interactive`，在 `output_validators/interactor` 中包含源码、`testlib.h` 和可执行的 `build/run` 适配器。题目 ZIP 导入时注册 executable，不依赖预先配置的 ID，也不需要手动选择 `special_run`。

适配器把 testlib AC/WA 转为 DOMjudge `42/43`，裁判异常保持为系统错误。输入是私有数据，答案是空文件；不要把空答案当作“任何输出都正确”。导出仍要求交互器和参考解通过验证。

DOMjudge 兼容基线为官方 9.0.1，完整平台验收尚未通过。本地验证、ZIP 结构检查和适配器测试不等于线上平台验收。正式比赛前，必须在实际判题环境检查编译配置、正确解、错误解、超时、裁判异常及文件隔离行为。

交互题不支持 FPS/QDUOJ 导出。无论使用哪种格式，都应检查目标判题机的编译标准、语言、资源限制和交互支持情况。

## 14. 常见限制与排错

| 现象 | 优先检查 |
| --- | --- |
| 沙箱尚未就绪 | Docker 是否运行、沙箱镜像是否准备完成、管理员设置中的检测结果 |
| Gen 复现检查失败 | 是否使用当前时间、未初始化变量、外部状态或未固定的随机源 |
| 普通题样例失败 | 输入输出是否填反、样例是否与最新版题面一致、标程与 Checker 是否正确 |
| 交互题一直等待 | 谁先发消息、每次发送是否 flush、EOF/结束条件是否一致 |
| 交互器读取输入失败 | 全交互输入严格为空；需要数据时应选半对拍并提供 `.in` |
| 裁判系统错误 | 交互器/Checker/Validator 是否崩溃、私有数据是否非法、testlib 判定是否正确 |
| 已有成功报告却不能导出 | 草稿是否修改、选中的发布版本是否完整验证、DOMjudge 是否混入 OI |
| PDF 预览不可用 | 是否开启 PDF、配置是否保存、竞赛是否选择了可用的发布版本 |
| PDF 缺字或生成失败 | 查看返回错误；检查字体、公式语法、附件格式、缺失图片和过度复杂的内容 |
| PDF 与当前草稿不同 | 竞赛使用发布版本；重新发布并选择新版本，不只是修改草稿 |
| HTTP 409 | 当前窗口版本过期，先保留本地改动再加载服务器版本 |
| HTTP 429 | 任务队列或 PDF 编译并发已满，等待已有工作结束后再试 |

默认单个测试文件上限为 64 MiB，题目测试数据总量上限为 512 MiB；管理员可用部署配置调整。手动文本测试点适合小数据，大文件使用上传。运行时间、测试点总数、输出量和全站任务队列还有独立上限，不应通过无限增加题目时限掩盖死锁。

PDF 一次支持 1–100 道题，题号为不重复的 1–3 位大写字母。题面与附件序列化总量不超过 20 MiB、单次编译最长 90 秒、全站最多同时编译 2 份任务。每题最多 20 个附件，单附件最多 1 MiB，导出图片总计最多 16 MiB；转换后的排版源文件总计最多 40 MiB。每份 PDF 最多 1000 页，一次任务生成的 PDF 总计最多 64 MiB。超限时缩减或拆分内容，不要单纯提高服务器任务时限。

Markdown 解析、附件校验和 PDF 编译在可取消的独立子进程中执行，超时或取消会终止该子进程。编译器仅能读取显式映射的模板、内置排版库、已校验图片和生成的题面，不能通过 Typst 读取宿主文件或任务 JSON，也不允许下载额外排版包。其 `384 MiB` 设置只限制 V8 的老生代堆，不限制 WASM 线性内存，也不是进程总内存硬上限。生产部署应保留容器/cgroup 内存约束并为并发生成留出资源；独立子进程不等同于选手程序的 Docker 隔离沙箱。

本地和容器环境均使用原项目锁定的 WASM 编译器版本（`0.6.1-rc5`），关闭编译器默认字体，只加载项目资产目录中的八款原字体，不扫描或回退到系统字体；字体文件缺失时直接报错。部署时需完整保留模板、字体及第三方许可文件。

私有数据、交互日志、答案和源码都属于制题资料。不要发送制题工程包给参赛者。AI 联网搜索只适合公开关键词，涉及未公开题目时应关闭搜索或指定不含私密内容的关键词。应用按账号隔离数据，但服务器运维权限仍能读取磁盘内容；定期备份并妥善保存备份和部署密钥。

## 15. 发布前检查清单

- 题意完整，普通题输入/输出格式或交互协议无歧义，约束与 Validator 一致。
- 题面预览没有重复栏目，公式、图片、样例和提示正确；旧题面已按需整理。
- 数据覆盖边界和错误解；Gen 可复现；全交互/半对拍输入约定明确。
- 标程及第二标准程序完成验证，Checker/交互器能够拒绝错误答案，不把裁判错误当成 WA。
- 发布名称明确，使用已验证的对应版本组赛；DOMjudge 竞赛只包含 ACM 题。
- 保存 PDF 配置并逐页查看题册，检查首页、题序、样例、分页、字体及所有图片。
- 在实际目标平台导入题包，提交正确、错误和超时程序，完成资源限制与隔离验收。
- 留存制题工程、发布包和验收记录；只向选手分发题面及允许公开的附件。
