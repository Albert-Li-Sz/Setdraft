# AI 对话网络搜索方案

状态：方案，尚未启用联网调用。目标是在现有独立 AI 对话中检索公开资料、显示可核对来源，兼容当前三种模型协议。

## 使用方式

输入框工具栏增加“联网搜索”开关，默认关闭，状态随对话保存；关闭时不触发搜索。开启后先检索，再流式回答。等待区依次显示“正在搜索”“已找到 N 个来源”“正在整理回答”，可停止；失败后保留问题和已有结果，允许重试，不把无来源的回答标成搜索结果。

答案中的引用编号链接到来源，底部可展开标题、域名、检索时间及短摘录。只接受服务端此次检索返回的来源 ID；模型生成的额外 URL 不冒充引用。普通成员只操作搜索开关，管理员在“管理员设置 → 搜索”选择提供方、配置密钥、测试连接与设置额度。

## 提供方选择

第一适配器选择 Tavily Search：HTTP POST 接口提供标题、URL、摘要，可控制语言、域名、时间范围及返回条数。首版使用 basic、最多 5 条、不索取提供方生成的答案或原始全文，统一交给现有模型总结。[官方接口](https://docs.tavily.com/documentation/api-reference/endpoint/search)

保留 SearXNG 适配器作为自部署选项：服务端 `/search` 请求 JSON，实例须明确启用 JSON 格式。它仍依赖上游搜索引擎，自部署不保证国内网络可达；不依赖未知公共实例。[官方接口](https://docs.searxng.org/dev/search_api.html)

上述选择是本项目的实施建议。提供方可用性须在目标服务器测试；首版不承诺某个商业 API 在所有国内网络可达，也不绕过上游限流。

## 服务边界与数据

增加 `SearchService.search({ query, language, domains, signal })`，返回规范化的 `SearchResult[]`；适配器负责鉴权、超时、响应解析、错误脱敏。ChatRequestQueue 编排“搜索 → 构建引用上下文 → 模型”，避免让 UI 或具体模型 SDK 了解提供方细节。首版只做一轮搜索，不要求模型支持工具调用；后续再加入最多两轮的 `web_search` 工具循环。

团队配置进入 identity.sqlite 的管理员配置区，密钥只在服务端使用；前端读取是否配置和额度。每次搜索的 query、结果摘要、时间、provider 与 chatRequestId 写入当前用户工作区。SSE 新增 search-start、search-results、search-failed 事件，复用持久化序号、取消和断线续接；重试同一请求复用已完成检索，用户主动“重新搜索”使用新请求 ID。

复用全站 AI 调度入口；搜索单独最多全站 4 个、每人 1 个，每次 10 秒，最多重试一次 429/暂时性服务错误，失败不阻塞普通聊天。管理员配置每人每日额度，计数持久化；结果缓存按用户与规范化查询隔离，默认 15 分钟，不能从缓存读取其他人的题目信息。额度耗尽时展示原因，不静默切换收费提供方。

## 信息与访问边界

搜索内容属于外部资料，作为工具数据加入上下文，不成为系统指令。只发送必要搜索词；默认不发送完整未发布题面、代码、附件、密钥或历史对话。开启开关时提示查询会发送到管理员配置的搜索服务。

首版不抓取任意网页，不接收客户端指定的上游地址。管理员配置的 SearXNG 地址有独立白名单，只能访问该搜索接口；结果链接只允许 HTTP(S)，拒绝凭据、脚本协议和本地文件协议。以后增加全文抓取时另设受限出口：检查 DNS 与每次重定向，拒绝私网/回环/链路本地/云元数据地址，限制内容类型、解压大小、跳转次数和时间。外部链接使用 noopener/noreferrer。

## 实施与验收

1. 共享结果契约、SearchService、Tavily 模拟适配器、管理员配置与额度。
2. ChatRequestQueue 单轮检索，SSE 持久化、取消、重试与引用校验。
3. 开关、等待动画、来源列表、中英文、键盘与窄屏检查。
4. 可选 SearXNG；真实服务器仅用管理员主动连接测试，不在自动测试中使用真实密钥或付费请求。

测试覆盖：开关关闭零请求、非法链接、提示注入文本、超时/429、取消、会话撤销、重复请求不重复计费、A/B 用户隔离、无结果、引用越界和续接不重复显示。上线前验证测试账户额度与来源追溯，不改变当前普通聊天的协议兼容性。
